# 截图使用场景与命名规范

## 一、三类场景

### 1. 取证（留证据 / 归档进知识库）

对象：订单系统回款列表、认领页、应收明细、微信聊天确认、邮件批复。
做法：

1. `--mode window --title 订单` 拍目标窗口（被遮挡也能拍，不必抢焦点）。
2. 若是长表格，用 `--count 3 --interval 1` 分张拍或先滚动再拍，**不要**用区域模式硬猜坐标。
3. 拍完读 `files[0].path`，用有意义的文件名归档（见下"命名规范"）。
4. 需要进知识库的，按 AGENTS.md 登记到 `99-Inbox\工作\` 对应子目录，并在 `INDEX.md` 补一行；金额类截图同时记 md5。

关键：**金额、日期、单号要在同一张图里可见**，不要拆成两张——避免后续对不上账。

### 2. 汇报配图（PPT / 文档 / 周报）

对象：系统看板、图表、报错界面、后台配置。
做法：

1. `--format png` 保清晰（PPT 里缩放会失真）。
2. 用 `--mode window` 而非全屏，**避免把无关窗口拍进去**（尤其别把自己正在聊天的窗口拍进去）。
3. 需要强调时用 `mask.py --box` 加红框圈注，不要在图上用画图工具手画。
4. 插进 PPT 前若需标注，先圈注再插入，保持全篇标注风格统一。

注意：PPT/汇报材料按知识库 40/45 号规范要求**用矢量图标、不贴位图**；截图只在"必须展示原始界面"时使用（如系统报错、后台数据）。

### 3. 外发（发客户 / 发同事 / 发群里）

**任何外发图先打码，再发。** 顺序不能反。

必遮字段（L2）：客户姓名与手机号、报价单价与总价、居间费、付款回单号与金额、身份证/银行卡号、其他客户的可识别信息。

```bash
# 遮盖两块敏感区（百分比写法，不用算像素）
"$PY" "$M" --in "{图}" --pct \
    --fill "12%,18%,28%,5%" \
    --fill "55%,62%,20%,4%" \
    --out "{图}_外发版.png"
```

打码尺度：

- 敏感信息用 `--fill`（纯色遮盖，不可逆）。马赛克/模糊存在被复原风险，只用于"降低可读性"而非"必须保密"的场合。
- 遮盖范围要比文字**各多留 6-10 像素**，防止边缘被辨识。
- 打码后**自己再打开看一眼**（用 Read 工具读图），确认没漏、没遮错位置，再交付。

## 二、命名规范

格式：`{对象}_{事项}_{日期}`，全中文可读，不用裸时间戳。

| 场景 | 示例 |
| --- | --- |
| 回款取证 | `某客户_回款列表_20261017.png` |
| 聊天确认 | `客户方_预付款到账确认_20261009.png` |
| 报错取证 | `Chrome_报错_ERR_CONNECTION_TIMED_OUT_20261013.png` |
| 汇报配图 | `Q3销售_业绩看板_20261010.png` |
| 外发版 | `{原名}_外发版.png`（保留原图，不覆盖） |

中文文件名的写法：脚本 `--tag` 传中文在 Git Bash 下可能乱码，两种稳妥做法——

1. 用 `--tag-b64`：`python -c "import base64;print(base64.b64encode('回款列表'.encode()).decode())"` 得到值再传；
2. 或先拍出来（`--tag` 用英文），再用 Bash `mv` 改成中文名——**推荐**，直观且不易错。

## 三、归档位置

| 用途 | 位置 |
| --- | --- |
| 临时/日常截图 | `~/Desktop/Screenshots/yyyy-MM-dd/`（脚本默认） |
| 项目证据（要进知识库） | `知识库\99-Inbox\{客户}\` 对应子目录，并在该目录 INDEX 登记 |
| 敏感原图（报价、回单） | 本地私密目录（如知识库的 80-私密），**不外发、不上云** |
| 桌面常用副本 | `桌面\{项目}\`（与知识库双份并存，两侧都不删） |
